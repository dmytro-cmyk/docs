## HTTP-коди відповіді

| Код | Опис |
|------|-------------|
| `200` | Успішно |
| `201` | Ресурс створено |
| `204` | Успішно, без вмісту |
| `401` | Не авторизовано — токен неправильний або не переданий |
| `403` | Доступ заборонено — немає прав |
| `404` | Не знайдено — ресурсу не існує |
| `405` | Метод не дозволено — ендпоінт не підтримує цей HTTP-метод |
| `413` | Завеликий запит — файл перевищує ліміт розміру |
| `422` | Помилка валідації — подробиці в полі `errors` |
| `429` | Перевищено ліміт запитів — дивіться заголовок `Retry-After` |
| `502` | Помилка шлюзу — збій зовнішнього сервісу (Telegram) |

## Формат відповіді з помилкою

Помилки, які повертає Zenedu API, мають формат JSON навіть без заголовка `Accept`. Відповіді проксі або CDN, сформовані до того, як запит потрапить до застосунку, можуть мати інший формат.

```json
{
  "message": "The given data was invalid.",
  "errors": {
    "field_name": [
      "The field_name is required."
    ]
  }
}
```

Тексти помилок у відповідях API завжди англійською.

## Бізнес-помилки

Коли запит коректний, але дія неможлива, поруч із `message` приходить машиночитаний `code`:

| Код | Статус | Значення |
|------|--------|---------|
| `unauthorized` | `403` | У користувача немає права на цю дію |
| `not_found` | `404` | Сутності немає в цьому боті |
| `conflict` | `409` | Дубль або поточний стан не дозволяє виконати дію |
| `limit_exceeded` | `422` | Обмеження тарифу не дозволяє виконати дію |
| `quota_exceeded` | `422` | Досягнуто захисний ліміт на кількість сутностей (`limit` у відповіді) |
| `pro_required` | `422` | Дія доступна на тарифі Pro |

Помилка `pro_required` додатково повертає `current_plan` (Pro, Basic, Trial або `null` без активної підписки) та `upgrade_url` — сторінку кабінету, де можна оновити тариф:

```json
{
  "message": "This action is available on the Pro plan. Upgrade your plan to continue.",
  "code": "pro_required",
  "current_plan": "Basic",
  "upgrade_url": "https://app.zenedu.io/workspace/billing"
}
```

## Ліміт запитів

Кількість запитів до API обмежена. У разі перевищення ліміту API повертає код `429` і заголовок `Retry-After` — через скільки секунд можна повторити запит.

## Помилки Telegram

Під час надсилання повідомлень через API Telegram може повернути помилки:

| Код | Значення |
|------|---------|
| `422` | Підписник заблокував бота або неактивний |
| `429` | Ліміт Telegram — дотримуйтеся заголовка `Retry-After` |
| `502` | Помилка авторизації в Telegram або збій доставки повідомлення |
