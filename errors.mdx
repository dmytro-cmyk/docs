## HTTP status codes

| Code | Description |
|------|-------------|
| `200` | Success |
| `201` | Resource created |
| `204` | Success, no content |
| `401` | Unauthorized — invalid or missing token |
| `403` | Forbidden — lacks permission |
| `404` | Not found — resource does not exist |
| `413` | Payload too large — file exceeds size limit |
| `422` | Validation error — check the `errors` field for details |
| `429` | Rate limit exceeded — check the `Retry-After` header |
| `502` | Bad gateway — external service (Telegram) failed |

## Error response format

```json
{
  "message": "The given data was invalid.",
  "errors": {
    "field_name": [
      "The field_name is required."
    ]
  }
}
```

## Business errors

When a request is valid but the action is not possible, the response carries a machine-readable `code` next to `message`:

| Code | Status | Meaning |
|------|--------|---------|
| `unauthorized` | `403` | The user lacks the permission for this action |
| `not_found` | `404` | The entity does not exist in this bot |
| `conflict` | `409` | A duplicate or the current state does not allow the action |
| `limit_exceeded` | `422` | A plan limit does not allow the action |
| `quota_exceeded` | `422` | The protective limit on the number of entities is reached (`limit` in the response) |
| `pro_required` | `422` | The action is available on the Pro plan |

The `pro_required` error also returns `current_plan` (Pro, Basic, Trial, or `null` without an active subscription) and `upgrade_url`, the dashboard page where the plan can be upgraded:

```json
{
  "message": "This action is available on the Pro plan. Upgrade your plan to continue.",
  "code": "pro_required",
  "current_plan": "Basic",
  "upgrade_url": "https://app.zenedu.io/workspace/billing"
}
```

## Rate limiting

API requests are subject to rate limiting. When the limit is exceeded, the API returns a `429` status code with a `Retry-After` header indicating how many seconds to wait before retrying.

## Telegram-specific errors

When sending messages through the API, Telegram may return errors:

| Code | Meaning |
|------|---------|
| `422` | Subscriber is blocked or inactive |
| `429` | Telegram rate limit — respect the `Retry-After` header |
| `502` | Telegram authentication failed or message delivery failed |
